# Plan: Control the phone from the computer with scrcpy

## The approved decisions

- **Flux gains no control of the phone.** No Go, Kotlin, QML or protocol
  code changes. Built-in control through Shizuku, an `AccessibilityService`
  or Flux's link is declined: it breaks the consent gate.
- **Arch:** `scrcpy` is an optional dependency, next to `mpv`. `ffmpeg` and
  SDL stay optional. Arch's `extra/scrcpy` 5.0.1 depends on
  `android-tools`, so `adb` comes with it, and there is no separate
  `android-tools` entry. `depends` is rejected: it would make `ffmpeg` and
  SDL hard dependencies.
- **Nix:** `scrcpy` and `android-tools` go in the default
  `runtimePackages` of both the NixOS and the Home Manager module, after
  `mpv`. Both are needed: nixpkgs' `scrcpy` finds `adb` by store path but
  doesn't put `adb` on the path, and the user needs `adb pair`. The cost is
  about 59 MiB (14 store paths). The opt-out is setting `runtimePackages`
  to a list without them, which replaces the whole default list, as today.
  No new Nix option such as `phoneControl.enable`.
  The flake pins `scrcpy` 5.0.1 and `android-tools` 37.0.0p1, and
  `lib.getName` gives `scrcpy` and `android-tools` (checked on 2026-11-15).
- **Checks:** two asserts in `nix/checks.nix` require both packages, one
  for the NixOS `good` config and one for the Home Manager `hm` config.
- **Starting it:** scrcpy's own launcher entries, **scrcpy** and **scrcpy
  (console)**, which both packages ship. No `flux-cli` subcommand, GUI
  button, Omarchy menu entry or `flux-cli doctor` line.
- **Connecting:** after `adb pair`, adb finds the paired phone by mDNS. Each
  session is: turn on **Wireless debugging**, open **scrcpy**. The fallback
  is one `adb connect <address>:<port>` with the port the phone shows.
- **Docs:** a new `### Control the phone with scrcpy` in `docs/camera.md`,
  a new `## scrcpy and adb` in `docs/security.md`, and one-line edits in
  `docs/security.md`, `docs/install.md`, `docs/android.md`,
  `docs/remote-input.md` and `skills/omarchy-flux/references/runtime.md`.
  They say that scrcpy is outside Flux, what adb grants, that it weakens
  Flux's tap consent while connected, and that a Flux unpair doesn't revoke
  it.
- **No new devShell.**


     ````markdown
     2. On the computer, run `adb pair` with the address, the pairing port, and the code that the phone shows:

        adb pair 192.168.1.20:37215
        ```

     2. Open **scrcpy** from the app launcher.

     3. If `adb` does not find the phone, run `adb connect` with the address and the port on the **Wireless debugging** page, then open **scrcpy** again:

        ```sh
        adb connect 192.168.1.20:41393
        ```

     With more than 1 device, run `adb devices` and pass the serial of the phone to scrcpy:

     ```sh
     scrcpy -s <serial>
     ```

     To stop, close the window, then turn off **Wireless debugging**.
     `adb` gives the computer a shell on the phone.
     See [scrcpy and adb](security.md#scrcpy-and-adb).
     ````

     ```markdown
     ## scrcpy and adb

     [scrcpy](camera.md#control-the-phone-with-scrcpy) controls the phone through `adb`, outside Flux.
     Flux itself never injects input on the phone.

     `adb` gives the computer a shell on the phone.
     It can install apps, read shared storage, grant permissions, and tap and type anywhere.
     Android's permissions still keep it out of the private data of other apps.
     That is more than any Flux feature grants.

     While `adb` is connected, software on the computer can tap the buttons of Flux on the phone: **Pair**, **Start**, **Play on phone**, and SSH signing with a screen lock that it knows.
     A tap then no longer proves that a person touched the phone.
     An approval that needs a fingerprint still needs one.
     So turn off **Wireless debugging** when you are done.

     The `adb` key is `~/.android/adbkey` on the computer.
     Each program of your user can use it, and the Flux settings do not limit it.
     While the `adb` server runs, it listens on `127.0.0.1:5037`, which other local users can reach too.

     A Flux unpair does not stop scrcpy or revoke `adb`.
     To remove 1 computer, open **Wireless debugging > Paired devices** on the phone and forget it.
     **Developer options > Revoke USB debugging authorizations** removes every computer, also the computers that you connected with a cable.

     Do not use `adb tcpip`.
     It has no pairing code and no encryption, and only a prompt on the phone protects it, the first time each key connects.
     ```

## Rollback

- Revert the PR's squash commit. Nothing in Flux depends on scrcpy, so a
  revert only removes the packages, the asserts and the docs.
- On NixOS and Home Manager, the next rebuild drops scrcpy and
  `android-tools`. On Arch, an installed `scrcpy` stays until the user
  removes it with `sudo pacman -Rs scrcpy`.
- A phone paired for adb stays paired after a revert. Forget the computer
  under **Wireless debugging > Paired devices**. On the computer, stop the
  adb server with `adb kill-server`; the key `~/.android/adbkey` stays until
  the user deletes it.
