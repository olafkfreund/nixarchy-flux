# Plan: A smaller Android APK

The approved spec decides:

- The release APK ships native libraries for `arm64-v8a` only.
- The debug APK ships `arm64-v8a` and `x86_64`, for the emulator workflow.
- Both are set with `ndk.abiFilters` in each build type, with no filter in
  `defaultConfig`. No ABI splits.
- The output names stay `app-release-unsigned.apk` and `app-debug.apk`.
  `fluxd`, `release.yml`, `SHA256SUMS` and the #44 first-install steps don't
  change.
- These stay as they are:
  - `buildTsnet` (arm64 only);
  - `useLegacyPackaging = true`;
  - the ML Kit dependencies;
  - the version-code scheme;
  - the application ID and signing.
- A CI step checks the ABIs of both APKs and logs their sizes. The unsigned
  release APK is uploaded as an artifact.
- The docs say that the app needs a 64-bit ARM device.
- Expected result: the release goes from about 50 MB to about 29 MB, and the
  debug APK from 95.2 MB to about 81.7 MB.

2. `.github/workflows/build.yml:124-131` (the `android` job).
   - After the step "Test and build APKs" (line 124), add:
     ```yaml
     - name: Check APK ABIs
       run: |
         check() { # apk, then the allowed ABIs in order
           apk=$1; shift
           got=$(unzip -Z1 "$apk" 'lib/*/*' | cut -d/ -f2 | LC_ALL=C sort -u | tr '\n' ' ') || got=
           [ "$got" = "$* " ] || { echo "::error::$apk has ABIs '$got', want '$*'"; exit 1; }
           unzip -Z1 "$apk" lib/arm64-v8a/libflux_tsnet.so >/dev/null || { echo "::error::$apk has no libflux_tsnet.so"; exit 1; }
           ls -l "$apk"
           unzip -lv "$apk" 'lib/*/*'
         }
         check app/build/outputs/apk/release/app-release-unsigned.apk arm64-v8a
         check app/build/outputs/apk/debug/app-debug.apk arm64-v8a x86_64
     ```
     The job's `working-directory: android` applies, so the paths are
     relative to `android/`.
   - After the `android-debug` upload (lines 126-131), add an upload with the
     same pinned action SHA:
     ```yaml
     - uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
       with:
         name: android-release-unsigned
         path: android/app/build/outputs/apk/release/app-release-unsigned.apk
         if-no-files-found: error
         retention-days: 14
     ```
     `upload-artifact` ignores `working-directory`, so this path starts with
     `android/`, like the existing upload.

   Verify:
   - `actionlint .github/workflows/build.yml`, if it's on the PATH.
   - Otherwise, parse the YAML:
     ```sh
     python3 -c 'import yaml,sys; yaml.safe_load(open(sys.argv[1]))' .github/workflows/build.yml
     ```
   - Test the `check` function locally on fixtures, under both `bash -e`
     (the job's default shell, since it sets no `shell:`) and
     `bash -eo pipefail`.
     - Copy the function from the YAML into `check.sh` in a temporary
       directory outside the repo, followed by the line `check "$@"`.
     - Make three zip fixtures with `python3 -m zipfile -c`:
       - `four.zip`: empty files at `lib/arm64-v8a/libflux_tsnet.so`,
         `lib/armeabi-v7a/a.so`, `lib/x86/a.so` and `lib/x86_64/a.so`;
       - `notsnet.zip`: only `lib/arm64-v8a/a.so`;
       - `nolib.zip`: only `a.txt`.
     - Each run is its own `bash` process, because `check` calls `exit`:

       | Fixture | Expected ABIs | Result |
       | --- | --- | --- |
       | `four.zip` | `arm64-v8a armeabi-v7a x86 x86_64` | exit 0 |
       | `four.zip` | `arm64-v8a x86_64` | exit 1, `has ABIs 'arm64-v8a armeabi-v7a x86 x86_64 '` |
       | `notsnet.zip` | `arm64-v8a` | exit 1, `has no libflux_tsnet.so` |
       | `nolib.zip` | `arm64-v8a` | exit 1, `has ABIs ''` |

   Traps:
   - The trailing space in `"$* "` is on purpose: `tr` leaves one after the
     last ABI.
   - The expected ABIs are listed in `LC_ALL=C` order: `arm64-v8a`,
     `armeabi-v7a`, `x86`, `x86_64`.
   - Keep `|| got=`, so an APK without `lib/` reaches the `::error::` line
     under `pipefail` as well. The spec says the job runs `bash -eo
     pipefail`; it runs `bash -e`, and the check works under both.
   - Pin the action by SHA, like every other `uses:` in the file.
