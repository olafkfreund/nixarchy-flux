# Plan: Clear the chat history on Android

## The approved decisions

- **Clear chat** is the last item of a computer's overflow menu
  (`ComputerMenu`). It shows only when that chat has a finished or failed
  entry.
  - It removes that computer's finished and failed entries: links, text,
    clips, scans, files and approval answers.
  - Running transfers stay, with their progress. Open approval requests
    stay. Other computers' chats stay.
  - No confirmation dialog. A toast: "Chat cleared" or "Chat and
    clipboard cleared", plus ". Files in progress stay." when a file of
    that computer still runs.
  - On a sample computer: "This is a sample computer".
- **Delete one entry**: a long press on a finished or failed entry opens a
  menu with Delete at the finger.
  - A long press inside a sent bubble's selectable text still selects
    text.
  - TalkBack reads each entry as one item with Delete in its actions.
  - No toast. A running file has no Delete.
- **The clipboard.** Clear chat, and Delete on the received clip (the
  owner chose yes), also empty the clipboard. They do so only when the
  clipboard holds the last clip that this computer sent:
  - the label is "Flux";
  - and the text, or the image address, is exactly the last one that
    this computer sent, recorded together with the computer's id.

  Anything else on the clipboard stays. The toast says "clipboard" only
  when the clear succeeded.
- **The log.** `SendLog.clear` and `SendLog.remove` run inside
  `_entries.update`. They keep running entries and never reset the id
  counter. The running count is taken inside the update.
- **Unchanged:** the protocol, `fluxd`, the desktop, iOS, macOS, `addSend`,
  `addClipIn`, the transfer functions, `ResumableTransfer`, the echo check,
  notifications and Downloads.

Three refinements of the spec's sketches, each recorded in Corrections
when its step is done:

- **P1 (step 4).** `EntryMenu` always wraps the entry in the same `Box`.
  For a running file it only turns off the long press, the TalkBack
  action and an open menu. With the spec's early `return content {}`, a
  file that finishes would change the composable's structure. Its
  remembered state would then reset; for example, a sent photo would load
  its thumbnail again.
- **P2 (step 2).** The computer and its clip are kept as one value, a
  `Pair` in one `@Volatile` field (`Plugins.lastRemoteFrom`,
  `ClipImage.lastRemoteFrom`), instead of the spec's separate id field.
  With two fields, a Clear could read the new computer's id with the old
  text while that text is still on the clipboard, and empty another
  computer's clip. With one value, the check sees either the old pair or
  the new one. If it sees the new pair, the clipboard still holds the old
  clip, which doesn't match, so the check fails safe.
- **P3 (step 4).** The menu anchor uses `AbsoluteAlignment.TopLeft` and
  `absoluteOffset`. The press position is measured from the left edge,
  and the app supports right-to-left layouts
  (`AndroidManifest.xml:70`, `supportsRtl`), where `offset` would mirror
  it.

     @Composable
     private fun EntryMenu(e: SendEntry, context: Context, content: @Composable (onText: (LayoutCoordinates) -> Unit) -> Unit) {
         val running = e.state == TransferState.Running
         var at by remember { mutableStateOf<IntOffset?>(null) }
         var self by remember { mutableStateOf<LayoutCoordinates?>(null) }
         var text by remember { mutableStateOf<LayoutCoordinates?>(null) }
         val delete = { deleteEntry(context, e) }
         Box(
             Modifier
                 .onGloballyPositioned { self = it }
                 .pointerInput(e.id, running) {
                     if (running) return@pointerInput
                     detectTapGestures(onLongPress = { p ->
                         // The selectable text keeps its own long press.
                         val s = self
                         val t = text
                         val box = if (s != null && t != null && s.isAttached && t.isAttached) s.localBoundingBoxOf(t) else null
                         if (box == null || !box.contains(p)) at = IntOffset(p.x.toInt(), p.y.toInt())
                     })
                 }
                 .semantics(mergeDescendants = true) {
                     if (!running) customActions = listOf(CustomAccessibilityAction("Delete") { delete(); true })
                 },
         ) {
             // A failed file that runs again closes its menu.
             LaunchedEffect(running) { if (running) at = null }
             content { text = it }
             if (!running) at?.let { p ->
                 // The press is measured from the left edge, also in a right-to-left layout.
                 Box(Modifier.align(AbsoluteAlignment.TopLeft).absoluteOffset { p }) {
                     DropdownMenu(expanded = true, onDismissRequest = { at = null }) {
                         DropdownMenuItem(text = { Text("Delete") }, leadingIcon = { Sym(Ic.delete) }, onClick = {
                             at = null
                             delete()
                         })
                     }
                 }
             }
         }
     }
