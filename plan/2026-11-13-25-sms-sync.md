# Plan: Text messages: no false "Not sent", no hidden stale thread

## The approved decisions

- **"Not sent" stays** for both cases: no report from the phone in 60 s,
  and a message the phone stored as failed. No label change, no label
  test, no label docs (owner, at the spec review; spec part 1).
- **The phone's clock.** Every `flux.sms.messages` packet gets an optional
  `now` field, the phone's time in milliseconds. fluxd uses it only when
  the phone is more than `smsClockSlack` (120 s) behind; then it moves the
  phone's message times by the measured gap before matching an outbox
  entry. Below 120 s, or with a phone ahead, or with no `now`, matching is
  exactly as today, so the link delay never moves a time. An older fluxd
  ignores the field. The slack itself stays 120 s.
- **Capability check.** `SendSms` refuses a send to a *connected, paired*
  phone that doesn't list `flux.sms.messages`, with `not_supported`. An
  offline phone still gets `offline`, an unpaired one `not_paired`.
- **A failed reload of an open thread shows.** The line above the message
  field shows "The thread may be out of date: <error>" with **Retry**. The
  messages stay. No automatic retry.
- **Conditional fixes** (step 6) ship only when the Pixel test or a unit
  test confirms the cause (spec part 5): MMS download notices (type 130)
  as "[MMS not downloaded]" (Pixel only); an unread MMS whose text arrives
  later is sent again (the unit test of 6b shows the gap in `SmsChanges`,
  so it ships in the first round); a troubleshooting entry for one number
  in two threads (Pixel only); a new issue for MMS read errors in the log.
- **No change:** no list request on connect, no sent intents, no MMS media
  (declined for now), no merge of split threads, no change for the
  startup MMS mark or the 200-message scan cap unless the test shows a
  message that a reload doesn't show, no same-second MMS ordering.
- **Docs:** the limits in troubleshooting; `docs/ipc.md` for the error
  code and the matching rule.
- **#25** gets one comment with a result per item after the Pixel test,
  and closes only when each item has a result and item 3 passed.
