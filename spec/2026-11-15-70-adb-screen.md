# Spec: Control the phone from the computer with scrcpy

The owner approved option (a) on 2026-11-15:
- Flux gains no control of the phone;
- on NixOS and Home Manager, installing Flux installs scrcpy and adb; on
  Arch they are an optional dependency (intent lines 112-113);
- the user starts scrcpy from the launcher, with one `adb connect` as the
  fallback when adb doesn't find the phone (intent lines 114-116);
- the docs explain Wireless debugging pairing and the adb key, which a Flux
  unpair does not revoke.

The change is packaging and docs only. No Go, Kotlin, QML or protocol code
changes. Two asserts are added to the Nix checks.

## Design

### 1. Arch package (`dist/arch/PKGBUILD:12-20`)

Add one optional dependency to `optdepends`, after `'mpv: the phone screen
mirror'` (line 16):

```bash
	'scrcpy: control the phone from the computer, with adb'
```

- It is optional, like `mpv` for the mirror, so `ffmpeg` and SDL stay
  optional (intent line 113). `pacman` lists it after the install.
- Arch's `extra/scrcpy` 5.0.1 depends on `android-tools`, `ffmpeg`,
  `libusb` and `sdl3`. So `adb` comes with it, and a separate
  `android-tools` entry isn't needed.

### 2. Nix modules (`nix/nixos.nix:30-48`, `nix/home-manager.nix:33-51`)

Add `scrcpy` and `android-tools` to the default `runtimePackages` in both
modules, after `mpv`. In both descriptions, change "Programs that fluxd
runs." to "Programs that fluxd runs, and scrcpy with adb to control the
phone." Keep the second sentence of each as it is.

- `runtimePackages` already holds tools a single feature needs, such as
  `mpv`, `gpu-screen-recorder` and `wf-recorder`. A Nix module has no
  optional dependencies, so the default list is the house way.
- Both are needed. nixpkgs' `scrcpy` finds `adb` by its store path, but it
  doesn't put `adb` on the path, and the user needs `adb pair`.
- Cost: about 59 MiB more on top of `ffmpeg`, `mpv`, `pipewire`,
  `gpu-screen-recorder` and `wf-recorder` (14 more store paths, measured
  with `nix path-info` on 2026-11-15). A user who doesn't want them sets
  `runtimePackages` to a list without them. That replaces the whole default
  list, as it does today.
- The flake has no devShell, and none is needed: this is for users, not
  for building Flux.

### 3. Nix checks (`nix/checks.nix`)

The checks only force each package to evaluate (`:80-84`, `:189-191`), so a
dropped package goes unnoticed. Add one assert to each config.

NixOS, next to the `ffmpeg` assert (`:87-89`):

```nix
assert lib.assertMsg (lib.all (
  n: lib.any (p: lib.getName p == n) good.environment.systemPackages
) [ "scrcpy" "android-tools" ]) "scrcpy and android-tools must be on the system path";
```

Home Manager, after the `hm.home.packages` assert (`:189-191`):

```nix
assert lib.assertMsg (lib.all (
  n: lib.any (p: lib.getName p == n) hm.home.packages
) [ "scrcpy" "android-tools" ]) "scrcpy and android-tools must be in home.packages";
```

`good` enables Flux without overriding `runtimePackages` (`:19-27,39`), and
`nixos.nix:90` puts the list on `environment.systemPackages`. The Home
Manager module puts it on `home.packages` (`home-manager.nix:119`).

### 4. The easy way to start it

No Flux code. Both packages ship scrcpy's own launcher entries,
**scrcpy** (`scrcpy.desktop`) and **scrcpy (console)**
(`scrcpy-console.desktop`). They are checked in the nixpkgs store path and
in Arch's file list. So scrcpy is in the Omarchy app launcher after the
Nix install, and on Arch after `sudo pacman -S --needed scrcpy`. The console entry shows scrcpy's errors in a terminal, for
example when no phone is connected.

The launcher is the main way to start it. It works without an adb command
when adb finds the paired phone by itself:
- After `adb pair`, adb finds the phone's Wireless debugging service by
  mDNS and connects to it. The Omarchy firewall lets mDNS in
  (`docs/security.md:169-170`).
- So each later session is: turn on **Wireless debugging** on the phone,
  then open **scrcpy** from the launcher.
- When adb doesn't find the phone, for example on another subnet, the
  fallback is one `adb connect <address>:<port>` with the port the phone
  shows, then the launcher again (intent lines 114-116).

The auto-connect is unverified on the owner's setup. Verification 5 tests
it after Wireless debugging is turned off and on, and tests the fallback.

### 5. Docs

- **`docs/camera.md`, Screen mirror (`:318-341`).** Line 329 becomes: "The
  desktop window shows the screen but does not control phone input. To
  control the phone, see [Control the phone with
  scrcpy](#control-the-phone-with-scrcpy)." A new subsection
  `### Control the phone with scrcpy` after line 341 says:
  - scrcpy is a separate app that streams and controls the phone over adb.
    It doesn't use Flux, its pairing or the Flux mirror.
  - It needs **Wireless debugging**, which needs Android 11 or later. On
    Android 10, which Flux supports (`docs/android.md:8`), use a USB cable
    with **USB debugging**.
  - Install: the NixOS and Home Manager modules install scrcpy and adb. On
    Arch, run `sudo pacman -S --needed scrcpy`, which brings `adb`.
  - First time: **Developer options > Wireless debugging > Pair device with
    pairing code**, then `adb pair <address>:<pairing port>` with the code.
    The pairing port and the connection port are different, as in [install
    with adb](android-setup.md#install-with-adb).
  - Each time: turn on **Wireless debugging**, then open **scrcpy** from the
    launcher. If nothing opens, open **scrcpy (console)** to see why. If
    adb doesn't find the phone, run `adb connect <address>:<port>` with the
    port on the **Wireless debugging** page. With more than one device,
    run `scrcpy -s <address>:<port>`.
  - Stop: close the window, then turn off **Wireless debugging**.
  - A link to [scrcpy and adb](security.md#scrcpy-and-adb).
- **`docs/security.md`.** A new section `## scrcpy and adb`, after Remote
  access (`:186-193`):
  - adb gives the computer a shell on the phone. It can install apps, read
    shared storage, grant permissions, and tap and type anywhere. Android's
    permissions still keep it out of other apps' private data. It is more
    than any Flux feature grants.
  - While adb is connected, software on the computer can tap Flux's own
    buttons on the phone: Pair, Start, Play on phone, and SSH signing with
    a screen lock it knows. A tap then no longer proves that a person
    touched the phone. Approvals that need a fingerprint still need one.
    That is why you turn off **Wireless debugging** when you are done.
  - The adb key is `~/.android/adbkey` on the computer. Each program of
    your user can use it, and Flux settings don't limit it. While the adb
    server runs, it listens on `127.0.0.1:5037`, which other local users
    can reach too.
  - A Flux unpair doesn't stop scrcpy or revoke adb. To remove one
    computer, open **Wireless debugging > Paired devices** on the phone and
    forget it. **Developer options > Revoke USB debugging authorizations**
    removes every computer, also those paired with a cable.
  - Don't use `adb tcpip`. It has no pairing code and no encryption; only a
    prompt on the phone protects it, the first time each key connects.
  - Flux itself never injects input on the phone.

  The unpair section gets one sentence after its list (`:234-237`), not a
  new bullet, because the list starts "ends every session of the device":
  "An unpair does not stop scrcpy or revoke adb. See [scrcpy and
  adb](#scrcpy-and-adb)." Line 12 becomes "To remove all Flux access for
  one device, [unpair it](#unpair-a-device)."
- **`docs/install.md:23`.** A new row after it: `| Phone control |
  \`scrcpy\`, which brings \`adb\`. See [control the phone with
  scrcpy](camera.md#control-the-phone-with-scrcpy) |`.
- **`docs/android.md:19`.** "You need `adb` only to install the APK from
  the computer, for example when Play Protect blocks it." becomes "You need
  `adb` to install the APK from the computer, for example when Play Protect
  blocks it, and for [scrcpy](camera.md#control-the-phone-with-scrcpy)."
- **`docs/remote-input.md:6`.** After "The computer does not control the
  phone or the Mac.", add: "To control an Android phone from the computer,
  see [scrcpy](camera.md#control-the-phone-with-scrcpy)."
- **`skills/omarchy-flux/references/runtime.md:171`.** After "The screen
  mirror does not provide phone input control.", add: "For control, the
  user runs scrcpy over adb, outside Flux. See `docs/camera.md`."

## Alternatives rejected

- **Built-in control through Shizuku, an `AccessibilityService` or Flux's
  link.** Declined by the owner: it breaks the consent gate
  (`docs/security.md:128-130,141-147`).
- **`depends` on Arch.** It would make `ffmpeg` and SDL hard dependencies
  of `omarchy-flux` for every user. Today `ffmpeg` is optional
  (`PKGBUILD:14`). The owner chose optional (intent line 113).
- **A `flux-cli` subcommand or a GUI button that runs scrcpy.** It
  duplicates scrcpy's launcher entries. Picking the right phone would need
  a map from a Flux device to an adb device, by address or mDNS, outside
  Flux's pinned-certificate identity. It would also make adb look like
  part of Flux.
- **An Omarchy menu entry in `dist/omarchy-menu.jsonc`.** It duplicates the
  launcher entries, and under `trigger.flux` it would present scrcpy as
  part of Flux.
- **A `flux-cli doctor` line for scrcpy** (`cmd/flux/doctor.go:132-149`
  checks mpv and wf-recorder). `fluxd` doesn't run scrcpy, and the package
  installs it.
- **`android-tools` as a separate Arch dependency.** `scrcpy` already
  depends on it.
- **A new Nix option, such as `phoneControl.enable`.** More code for two
  packages. `runtimePackages` is already the switch.
- **Docs only, with no package.** The intent asks for the packages.

## Risks

- **Larger Nix installs.** About 59 MiB more for Nix module users.
  Accepted by the intent. The opt-out is overriding `runtimePackages`.
- **Arch users miss the optional dependency.** The camera.md section and
  `install.md` give the `pacman` command.
- **adb auto-connect may not work on every network.** Then each session
  needs `adb connect`, which the docs give as the fallback. Verification 5
  checks it on the owner's network.
- **The adb key outlives the user's attention.** The docs say how to forget
  the computer, and to turn off Wireless debugging. Flux can't enforce
  either.
- **adb weakens Flux's tap consent while it is on.** The docs say so in
  security.md. Fingerprint approvals keep their check.
- **Readers take scrcpy as part of Flux.** camera.md and security.md both
  say it is outside Flux.
- **Wireless debugging behavior varies.** Android turns it off on another
  Wi-Fi network, and Samsung's Auto Blocker can block adb
  (`docs/android-setup.md:73`). The docs link the existing setup page.
- **nixpkgs renames a package.** The evaluation checks and the new asserts
  fail `nix flake check`.

## Verification

1. `nix flake check` passes, with the two new asserts.
2. To see the asserts bite, remove `android-tools` from one default list
   locally: `nix flake check` fails with the matching message. Put it back.
3. `bash -n dist/arch/PKGBUILD`, and
   `bash -c 'source dist/arch/PKGBUILD; printf "%s\n" "${optdepends[@]}"' | grep '^scrcpy: '`
   prints the new line, and the same with `"${depends[@]}"` prints no
   `scrcpy`. On an Arch machine, `makepkg --printsrcinfo` shows
   `optdepends = scrcpy: control the phone from the computer, with adb`.
4. Each new anchor exists:
   `grep -n '^### Control the phone with scrcpy' docs/camera.md` and
   `grep -n '^## scrcpy and adb' docs/security.md`.
5. **Owner, on the owner's phone and computer** (agents don't run adb
   against them):
   1. after the rebuild, `which scrcpy adb` finds both, and **scrcpy** and
      **scrcpy (console)** are in the launcher;
   2. pair with **Wireless debugging** and `adb pair`;
   3. turn **Wireless debugging** off and on, then open **scrcpy** from the
      launcher with no adb command: the phone shows, and a click and typing
      reach it. If it doesn't connect, run one `adb connect` with the port
      the phone shows, open the launcher again, and report which path
      worked;
   4. unpair the phone in Flux: scrcpy still connects, as the docs say;
   5. forget the computer under **Wireless debugging > Paired devices**:
      the next connection fails until `adb pair` runs again.
