# Spec: A smaller Android APK

The owner approved the intent with the proposed answers:
- the release ships `arm64-v8a` only;
- no ABI splits;
- other size cuts are out of scope.

The Codex and agy intent reviews corrected four points, which this spec
carries:
1. Only the **tailnet node** is arm64-only today. The app itself runs over the
   local network on other ABIs.
2. Use `ndk.abiFilters`, not `splits`, so the Gradle output names stay the
   same.
3. Debug keeps **both** `arm64-v8a` and `x86_64`.
4. "Version code" means the existing version-code scheme.

## Measurements

These come from the CI debug APK of `build.yml` run 43272624546 (`8df2630`,
95.2 MB). Its native libraries are the same files a release build ships.

| ABI | Stored in the APK | Raw | Main files |
| --- | --- | --- | --- |
| `arm64-v8a` | 15.4 MB | 37.8 MB | `libflux_tsnet.so` 8.5 MB, `libmlkit_google_ocr_pipeline.so` 4.7 MB, `libbarhopper_v3.so` 2.2 MB |
| `x86` | 7.9 MB | 17.7 MB | ML Kit OCR and barcode |
| `x86_64` | 7.6 MB | 17.6 MB | ML Kit OCR and barcode |
| `armeabi-v7a` | 5.6 MB | 10.1 MB | ML Kit OCR and barcode |

- `jniLibs.useLegacyPackaging = true` (`build.gradle.kts:83`) stores the
  libraries compressed. Upstream's 58.6 MB figure in the issue is therefore
  not what this fork pays.
- Removing the three other ABIs saves **about 21 MB** from every release
  APK. That is the download from GitHub and the transfer to each phone.
- That is about 50 MB down to about 29 MB, roughly 42% smaller. The
  intent's "71 MB down to 26 MB" came from upstream's uncompressed figures,
  which don't apply to this fork. The fork's APK also carries the 8.5 MB
  tailnet node.
- The size of the extracted native libraries on a phone does not change,
  because Android extracts only the device's own ABI. The APK that Android
  keeps on the phone does get smaller.
- Every `arm64-v8a` library has ELF `LOAD` alignment of at least 16 KB
  (`readelf -lW`): `0x4000`, and `0x10000` for `libflux_tsnet.so`. That is
  the alignment Android requires for 16 KB-page devices. It is not a runtime
  test on such a device, and the owner's Pixel uses 4 KB pages
  (`getconf PAGE_SIZE` gives 4096). The filter doesn't change these files.
- The size of the release APK itself is measured in Verification, because
  the fork has no release yet.

## Design

### 1. ABI filters (`android/app/build.gradle.kts:56-63`)

In `buildTypes`, set the filter in each build type, and none in
`defaultConfig`. That way no list depends on how AGP merges filters:

```kotlin
buildTypes {
    release {
        // shortcut: arm64 only (#23). The tailnet node exists only for
        // arm64-v8a, and every supported device is 64-bit ARM. Add an ABI
        // here, and to buildTsnet, if a device needs one.
        ndk { abiFilters += "arm64-v8a" }
        // existing signingConfig, minify, shrink, proguard lines
    }
    debug {
        // x86_64 keeps the emulator workflow of docs/android.md.
        ndk { abiFilters += listOf("arm64-v8a", "x86_64") }
    }
}
```

- The outputs stay `app-release-unsigned.apk` and `app-debug.apk`. So
  `release.yml:113`, `build.yml:129` and the docs need no change.
- These stay as they are:
  - `buildTsnet` (arm64 only);
  - `useLegacyPackaging`;
  - the ML Kit dependencies;
  - the version-code scheme (`release.yml:42-46`, `FLUX_VERSION_CODE`);
  - the application ID and signing.
- The x86_64 debug build still has no tailnet node, as today.

### 2. ABI check in CI

Add a step to `build.yml`'s `android` job, after "Test and build APKs".
GitHub runs it with `bash -eo pipefail`, but each check exits by itself, so
the step does not depend on that:

```sh
check() { # apk, then the allowed ABIs in order
  apk=$1; shift
  got=$(unzip -Z1 "$apk" 'lib/*/*' | cut -d/ -f2 | LC_ALL=C sort -u | tr '\n' ' ') || got=
  [ "$got" = "$* " ] || { echo "::error::$apk has ABIs '$got', want '$*'"; exit 1; }
  unzip -Z1 "$apk" lib/arm64-v8a/libflux_tsnet.so >/dev/null || { echo "::error::$apk has no libflux_tsnet.so"; exit 1; }
  ls -l "$apk"
  unzip -lv "$apk" 'lib/*/*'
}
check app/build/outputs/apk/release/app-release-unsigned.apk arm64-v8a
check app/build/outputs/apk/debug/app-debug.apk arm64-v8a x86_64
```

Also upload `app/build/outputs/apk/release/app-release-unsigned.apk` as the
artifact `android-release-unsigned`, with 14 days of retention like
`android-debug`. It has no signature, so it cannot be installed. It lets the
release's libraries be checked with `readelf`.

What the check catches:
- a change to the filters, to AGP or to the packaging that brings back other
  ABIs;
- `x86_64` disappearing from debug;
- the tailnet node going missing.

A new dependency with extra ABI folders does **not** fail it: the filter
strips those folders before packaging. The step logs both APK sizes and
every library's stored size. `release.yml`'s `files` job needs `build`, so
the check also runs on each release tag.

- `docs/install.md:7`: "The Android app requires Android 10 or later on a

## Alternatives rejected

- **ABI splits with a universal APK** (the issue's proposal).
  - Several signed APKs and a version-code suffix per ABI, which clashes
    with `release.yml:46`.
  - An ABI field from the app, and selection in `fluxd`.
  - The phone's installer only accepts `flux-android-VERSION.apk`
    (`docs/android.md:96-99`).
  - All that for the same arm64 result.
- **Keep `armeabi-v7a`.** About 5.6 MB more, for 32-bit devices that never
  had the tailnet node. The owner chose arm64 only.
- **A filter in `defaultConfig` plus an extra debug filter.** Whether AGP
  takes the union or overrides is easy to get wrong. A filter in each build
  type is explicit, and the CI check verifies it.
- **Play-delivered ML Kit models.** Out of scope. They would break offline
  and Google-free scanning.

## Risks

- **A 32-bit or x86 Android device.** The release fails to install with
  `INSTALL_FAILED_NO_MATCHING_ABIS`. The fix:
  - add the ABI to the release filter and to the CI check's list, about
    5-8 MB;
  - add it to `buildTsnet` too, about 8.5 MB more, if that device needs the
    tailnet node.

  The owner's connected device, a Pixel 11 Pro XL, is `arm64-v8a`.
- **x86_64 Chromebooks and emulators with ARM translation.** These now
  install the arm64 APK under translation. Before, the x86_64 ML Kit
  libraries made Android pick x86_64.
  - Whether the tailnet node then runs is unverified and depends on the
    platform. It is a separate executable, and translation of a separate
    process is not guaranteed.
- **An x86_64 device without translation** (Waydroid without
  `libndk_translation`) can only use the debug APK.
- **The CI check only guards the packaging.** A new dependency's arm64
  library still makes the APK larger without failing anything. The logged
  sizes show it.

## Verification

1. `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease`
   runs in CI (`build.yml`), dispatched on the branch.
   - `assembleRelease` also runs `lintVitalRelease`.
   - The new ABI check must pass:
   - release: `arm64-v8a` only, with `libflux_tsnet.so`;
   - debug: `arm64-v8a` and `x86_64`.
2. Sizes:
   - Compare the branch's `android-debug` artifact with master's 95.2 MB.
     The expected saving is about 13.5 MB (`armeabi-v7a` and `x86`).
   - Take the size of `app-release-unsigned.apk` and its `lib/` listing from
     the new step's log. The stored total must match the arm64 row above
     (about 15.4 MB). Then the saving against an unfiltered release built
     from the same revision is the 21.1 MB of the three dropped ABIs.
3. Locally, `readelf -lW` on the arm64 libraries of the
   `android-release-unsigned` artifact: every `LOAD` is aligned to 16 KB or
   more.
4. Smoke test before merge: install the branch's CI `android-debug` APK on
   the owner's Pixel with `adb install`. Flux is not installed there now. It
   has the same arm64 libraries as the release. Check that:
   - text recognition and barcode scanning in the camera work;
   - the tailnet node starts, if Tailscale is configured.

   Uninstall it afterwards, so the v0.20.0 first install starts clean.
5. Release check after merge: the v0.20.0 first install (#44's
   `docs/releasing.md` steps) installs the signed release on each device.
   Repeat the step 4 checks there.
6. `nix flake check path:.` passes. The Go side is untouched.
