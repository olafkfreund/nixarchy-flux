# Spec: Install and configure Flux on NixOS with a flake

## Design

### Flake outputs (`flake.nix`, `flake.lock`)

- Input: `nixpkgs` (nixos-unstable, which has `go_1_27` 1.27.3; `go.mod`
  needs 1.27.1). No other inputs.
- Systems: `x86_64-linux`, `aarch64-linux`.
- `packages.<system>`:
  - `flux-core` — `buildGoModule` (with `go = go_1_27`) building
    `./cmd/fluxd`, `./cmd/flux` (renamed to `flux-cli`) and
    `./cmd/flux-approve` (with `CGO_ENABLED=0`, like `Makefile:30`, built in
    a separate `buildGoModule` pass or via `env` per binary). It installs
    what `make install` installs except the GUI: `lib/flux/flux-approve`,
    `lib/flux/bin/flux` → `../../../bin/flux-cli` (the short name stays out
    of `bin/`, `Makefile:53`), `share/flux/omarchy-plugin` (same layout as
    the `copy-plugin` macro, `Makefile:16-21`, so `plugin.Installed(exe)`
    at `internal/plugin/plugin.go:30` finds it next to `bin/`),
    `lib/udev/rules.d/61-flux-v4l2loopback.rules`, desktop entry and icons.
    No `post-install.sh`, no `/etc/profile.d`.
  - `flux-gui` — `stdenv.mkDerivation` with `cmake`, `ninja`,
    `qt6.wrapQtAppsHook`, inputs `qtbase qtdeclarative qtsvg qtwayland`
    (`gui/app/CMakeLists.txt:9`, PKGBUILD `depends`). Separate, so
    `nix run .#flux-cli` does not pull Qt.
  - `flux` (= `default`) — `symlinkJoin` of both. `flux-cli open` finds
    `flux-gui` in `PATH` when it is not next to the binary
    (`cmd/flux/open.go:114`).
- `apps.<system>.flux-cli` → `flux-core/bin/flux-cli`, so
  `nix run .#flux-cli -- doctor` works.
- `overlays.default` adding the three packages.
- `nixosModules.default`, `homeManagerModules.default` (below).
- `checks.<system>`: the packages (Go tests run in `checkPhase`), plus a
  module-evaluation check for each module (a minimal `nixosSystem` /
  `homeManagerConfiguration`-free `lib.evalModules` with stubs, so the
  flake needs no home-manager input).
- `formatter` = `nixfmt-rfc-style`.

Version: `-X main.version=<v>` for both `cmd/flux` and `cmd/fluxd`, where
`<v>` is the version in `nix/version.nix` (`0.19.1`, the last tag) plus
`+<shortRev>` from `self.shortRev or "dirty"`. A `scripts/`-free manual bump
of `nix/version.nix` follows each upstream merge.

### Go changes (small, all behind one build-time value)

A new package-level `var packager = ""` in `cmd/flux`, and
`approve.HelperPath` changes from `const` to `var` (with `PAMLine` built
in a function, since a `const` cannot use a `var`). The flake sets
`-X main.packager=nix` and
`-X flux/internal/approve.HelperPath=$out/lib/flux/flux-approve`. With
`packager` empty, every code path is the same as today, so Arch and
`make install` do not change.

When `packager == "nix"`:

| Command | Today | On Nix |
| --- | --- | --- |
| `flux-cli setup` service step (`cmd/flux/setup.go:180`) | writes or removes a user unit | prints that the NixOS or Home Manager module owns `fluxd.service`, writes nothing |
| `flux-cli setup` system report (`setup.go:365`) | `post-install.sh`, pacman hints | names the module options |
| `flux-cli setup` plugin step | copies real files | unchanged |
| `flux-cli update` (install) (`update.go:60`) | pacman, else source hint | says to update the flake input and rebuild |
| `flux-cli update --check`, `--phone` | — | unchanged |
| `flux-cli approve enable` / `disable`, the PAM half of `setup` and `remove` | rewrite `/etc/pam.d` | refuse, naming `services.flux.approve.services` |
| `flux-cli approve enroll` / `status` / key removal | — | unchanged (they write `/etc/flux/approve`, user state) |

Each change is a guard at the top of the existing function, with a test
for the nix branch in the existing `_test.go` next to it.

### Service and restart behaviour

fluxd is **not** wrapped with `makeWrapper`: `internal/upgrade.Self`
(`internal/upgrade/upgrade.go:29-45`) compares the stat of `argv[0]` with
`/proc/self/exe`, so a shell wrapper would look like a replaced binary and
fluxd would restart in a loop.

Instead, `ExecStart` is the stable profile path, not the store path:

- NixOS module: `/run/current-system/sw/bin/fluxd`.
- Home Manager module: `${config.home.profileDirectory}/bin/fluxd`.

A rebuild re-points that link to a new store file with a new inode;
fluxd's watcher sees it and exits 75 after transfers and streams end, and
`RestartForceExitStatus=75` restarts it. That is the upstream behaviour,
and the unit sets `X-RestartIfChanged=false` / `restartIfChanged = false`
so the switch itself never cuts a transfer.

The unit is the content of `dist/fluxd.service` with
`ExecReload=${coreutils}/bin/kill -HUP $MAINPID` and `Type=exec`.

Tools that fluxd calls by name (`pw-record`, `pw-cat`, `pactl`, `ffmpeg`,
`wtype`, `mpv`, `gpu-screen-recorder`, `wf-recorder`, `xkbcli`, `ss`,
`ssh-keygen`, `wl-copy`, `xdg-open`) come from `PATH`. NixOS's user
manager `DefaultEnvironment` PATH includes `/run/current-system/sw/bin`
and `/etc/profiles/per-user/%u/bin`, so each module adds an option
`runtimePackages` (default: `pipewire pulseaudio ffmpeg wtype mpv
gpu-screen-recorder wf-recorder libxkbcommon iproute2 openssh wl-clipboard
xdg-utils`) to `environment.systemPackages` / `home.packages`. Desktop
tools (`hyprctl`, `omarchy-shell`, `herdr`, `systemctl`) come from the
desktop itself.

### NixOS module (`nix/nixos.nix`), `services.flux`

| Option | Default | Effect |
| --- | --- | --- |
| `enable` | `false` | adds `package` and `runtimePackages` to `environment.systemPackages`, `services.udev.packages = [ package ]`, `services.avahi.enable` / `publish.enable` / `publish.userServices` as `mkDefault true` (fluxd publishes over Avahi D-Bus, `internal/lan/mdns.go`) |
| `package` | `pkgs.flux` from the flake | |
| `runtimePackages` | list above | |
| `users` | `[ ]` | defines `systemd.user.services.fluxd` with `unitConfig.ConditionUser = map (u: "\|" + u) users`, so it runs only for these users. Empty: no unit, as today (no account is announced until it opts in) |
| `openFirewall` | `false` | TCP 12100–12108, UDP 12100 (`internal/lan/tls.go:15-17`). Off by default: fluxd dials out, which works with a closed firewall (README) |
| `webcam.enable` | `false` | `boot.extraModulePackages = [ kernelPackages.v4l2loopback ]`, `boot.kernelModules = [ "v4l2loopback" ]` |
| `webcam.moduleOptions` | `"devices=0"` (nullable) | `boot.extraModprobeConfig` line; set `null` when the host already configures v4l2loopback (`post-install.sh:14-20` keeps existing options) |
| `approve.services` | `[ ]` | for each of `sudo`, `hyprlock`, `polkit-1` (assertion: only these, never `sshd`/`login`, `pam.go:27`): `security.pam.services.<s>.rules.auth.flux = { control = "sufficient"; modulePath = "${pam}/lib/security/pam_exec.so"; args = [ "quiet" "stdout" "${package}/lib/flux/flux-approve" ]; order = config.security.pam.services.<s>.rules.auth.unix.order - 10; }` — same line as `PAMLine`, placed just before the password rule. Unlike `AddPAMLine`, which puts it first, this keeps earlier guards such as `pam_faillock` preauth in effect |

`/etc/flux/approve` stays writable user state that `approve enroll`
creates; the module does not manage it.

### Home Manager module (`nix/home-manager.nix`), `services.flux`

| Option | Default | Effect |
| --- | --- | --- |
| `enable` | `false` | `home.packages = [ package ] ++ runtimePackages`; `systemd.user.services.fluxd` (same unit, HM syntax, `X-RestartIfChanged = false`) |
| `package`, `runtimePackages` | as above | |
| `plugin.enable` | `true` | `home.activation` step: when `~/.config/omarchy/plugins/flux` is missing, copy `${package}/share/flux/omarchy-plugin` there as real files (`cp -rT --no-preserve=mode`), never a symlink (`setup.go:315`). After that, fluxd keeps it at its own version (`cmd/fluxd/upgrade.go:117`). Turning it on in the bar stays `flux-cli setup` / `omarchy plugin enable` |

System parts (udev, avahi, PAM, webcam, firewall) are only in the NixOS
module. Use the NixOS `users` option **or** the Home Manager module for a
given user, not both; the README section says so. (Both define a unit
named `fluxd.service`; the HM one wins for that user, which is harmless
but redundant.)

### Docs

`docs/nix.md`: flake input, a NixOS example, a Home Manager example, what
`flux-cli setup` still does on Nix. One line in `README.md` and
`docs/install.md` linking it.

## Alternatives rejected

- **One derivation with Go and Qt**: `nix run .#flux-cli` would build Qt.
- **`makeWrapper` around fluxd with a fixed `PATH`**: breaks the
  replaced-binary watcher (above), and pins heavy media tools into every
  closure.
- **`ExecStart` at the store path + `restartIfChanged = true`**: a switch
  cuts active transfers and streams.
- **Patching the FHS paths with `substituteInPlace`** instead of `-X`:
  breaks silently when upstream moves a line. `-X` on a renamed symbol is
  also ignored silently, so a check asserts `flux-cli version --json` (or
  a `strings` grep) shows the nix packager and helper path.
- **Generating `~/.config/flux` settings from Nix**: the app and the phone
  write those settings; Nix-managed files would be read-only.
- **A home-manager flake input** for module checks: adds a large input for
  one eval check; `lib.evalModules` with stubbed options is enough.
- **Fixing the review's security findings here**: separate issues, per the
  approved intent.

## Risks

- **Go tests in the sandbox**: some may need D-Bus, `/run/user`, or tune
  network buffers (`TestSlowClientDoesNotBlock`, issue #22). Mitigation:
  `checkFlags = [ "-skip=<names>" ]` for tests that fail only in the
  sandbox, each listed with a reason.
- **`vendorHash`** changes with every `go.mod` bump from upstream; the
  build fails with the new hash, which is then pasted in.
- **User-manager PATH**: checked on this Nixarchy host,
  `systemctl --user show-environment` has `/run/current-system/sw/bin` and
  `/etc/profiles/per-user/<user>/bin`. If a desktop starts the user manager with a
  smaller `PATH` (some uwsm setups), fluxd misses tools. `flux-cli doctor`
  shows it; fix is `systemd.user.services.fluxd.path`.
- **`ConditionUser` with `|`**: OR semantics for triggering conditions;
  to verify on a real host that a non-listed user gets no fluxd.
- **PAM `order`**: must land before `pam_unix`; checked by evaluating
  `config.security.pam.services.sudo.text` in a check.
- **polkit-1**: polkit 126+ runs its helper as a system service that
  cannot reach fluxd's socket (`cmd/flux/approve.go:91-96`); allowed in the
  option, documented as likely not working.
- **`approve status` from another build** (e.g. `nix run`) compares a
  different store `HelperPath` and reports "not enabled". Low impact,
  documented.
- **Immutable `/etc`** (`system.etc.overlay.mutable = false`): `approve
  enroll` cannot write `/etc/flux/approve`. Documented; out of scope.
- **Upstream merges** touching the guarded functions conflict in at most
  the guard lines.

## Verification

Local only, no host switch:

1. `nix flake check` — builds `flux-core` (Go tests pass), `flux-gui`,
   both module eval checks, and the PAM-order check.
2. `nix build .#flux && ls result/bin result/lib/flux result/share/flux/omarchy-plugin`
   — `fluxd flux-cli flux-gui`, `flux-approve`, `bin/flux`, plugin with
   `manifest.json` and `Flux/`; no `bin/flux`.
3. `nix run .#flux-cli -- version` prints `0.19.1+<rev>`.
4. `go test ./cmd/... ./internal/...` and `make build` still pass outside
   Nix (Arch path unchanged), and `go vet` / `gofmt` as in `Makefile:44`.
5. `file result/lib/flux/flux-approve` reports statically linked.
6. Owner's manual smoke check on a Nixarchy desktop (after the owner
   chooses to switch): `flux-cli doctor` is clean, `flux-cli open` shows
   the GUI on Wayland, a phone pairs, and a rebuild during a transfer does
   not cut it.
