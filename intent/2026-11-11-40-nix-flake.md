# Intent: Install and configure Flux on NixOS with a flake

## Problem

Flux installs only through the Arch `PKGBUILD` (`dist/arch/PKGBUILD`) or
`make install`. Neither works on NixOS:

- `make install` writes `/etc/profile.d/flux-path.sh` even with
  `PREFIX=$out`, then runs `dist/post-install.sh`, which writes
  `/etc/modprobe.d`, `/etc/modules-load.d`, loads kernel modules and restarts
  user services (`Makefile:58-78`, `dist/post-install.sh`).
- The code hard-codes FHS paths: the PAM helper at
  `/usr/lib/flux/flux-approve` (`internal/approve/pam.go:12`), `pam_exec.so`
  at `/usr/lib/security` (`cmd/flux/approve.go:177`), the polkit helper
  (`cmd/flux/approve.go:89`), the packaged user unit at
  `/usr/lib/systemd/user/fluxd.service` (`cmd/flux/setup.go:79`), and
  `/bin/kill` in `dist/fluxd.service`.
- `flux-cli approve enable` rewrites `/etc/pam.d/<service>` in place
  (`internal/approve/pam.go:123,282`), which fights NixOS's managed PAM files.
- `flux-cli setup` writes its own user unit when it does not find the
  packaged one, which can pin an old store path (`cmd/flux/setup.go:182`).
- `flux-cli update` and fluxd's daily self-update replace binaries, which
  cannot work in the read-only store (`internal/upgrade`, `cmd/flux/update.go`).
- fluxd calls about 25 external tools from `PATH` (pw-record, ffmpeg, wtype,
  mpv, gpu-screen-recorder, wf-recorder, hyprctl, omarchy-shell, xkbcli, …).

## Proposed outcome

On a NixOS (Nixarchy) machine a user can add this repo as a flake input and:

- `nix build .#flux` gives `fluxd`, `flux-cli` (and `flux`), `flux-approve`,
  `flux-gui`, the omarchy-shell plugin files, desktop entry and icons.
- `nix run .#flux-cli -- doctor` works without installing anything.
- A NixOS module (`services.flux.enable`) sets up what `post-install.sh` and
  the PAM step do today, declaratively: the fluxd user service, the
  v4l2loopback module and udev rule, optional fingerprint approval in PAM,
  and the firewall ports if they are needed.
- A Home Manager module enables fluxd and the omarchy-shell plugin for one
  user, for machines where the system module is not used.
- `nix flake check` builds the package and runs the Go tests.
- Self-update is off for Nix installs, and `flux-cli update`/`setup`/`approve`
  say to change the Nix config instead of mutating the system.

## Affected users and systems

- Users of this fork on NixOS / Nixarchy desktops (Hyprland, omarchy-shell).
- New files: `flake.nix`, `flake.lock`, `nix/` (package and modules).
- Small Go changes so the code finds its helpers in a Nix prefix and turns
  off self-update when built by Nix (`internal/approve`, `cmd/flux`,
  `internal/upgrade`).
- Not affected: Android, iOS, macOS and Windows apps; the Arch package keeps
  working as today.

## Constraints

- Must keep the Arch/`make install` path working unchanged, so upstream
  changes keep merging cleanly. Go changes stay small and behind a build-time
  setting (for example an `-ldflags -X` value) instead of rewrites.
- Must not mutate `/etc` or the store at run time on NixOS. PAM changes go
  through `security.pam.services.*`, not `flux-approve enable`.
- PAM approval is a `sufficient` auth rule: it must be opt-in and off by
  default, per service.
- `go.mod` needs Go 1.27.1; the flake must pin a nixpkgs that has it (or
  override `go`).
- Building or switching on a host is the owner's call; no deploy as part of
  this task.

## Open questions

1. Scope: Linux desktop only (daemon, CLI, Qt GUI, plugin), with the
   Android APK left to the existing Gradle build? Recommended: yes.
2. Modules: both a NixOS module and a Home Manager module, or NixOS only?
   Recommended: both, Home Manager covering the per-user service and plugin.
3. Should the Codex review's security findings in fluxd (symlinked browse
   roots, resumable transfers bypassing the disk-space check, empty release
   signing key) be fixed in this task or tracked as separate issues?
   Recommended: separate issues, so this task stays packaging.
